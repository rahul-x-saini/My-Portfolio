01 / Flagship

Adaptive Corrective RAG (CRAG)

Retrieval quality evaluation with sentence-level knowledge refinement.

LangGraphFAISS OpenAITavily Pydantic
GitHub ↗

Problem

Traditional RAG blindly trusts whatever gets retrieved — bad retrieval silently becomes a bad, hallucinated answer.

Approach

Rebuilt the Corrective-RAG paper's architecture from scratch: an LLM-based evaluator scores retrieved documents and routes each query through internal retrieval, web-search fallback, or a hybrid path — with sentence-level decomposition and relevance filtering before generation, and Pydantic-validated structured routing throughout.

Result

A working implementation of the paper's full control loop (evaluate, route, refine, generate) with logging and error handling at every stage, so a failed step degrades gracefully instead of crashing the pipeline.

02 / Deployed

AI Resume Screener

Production API and microservice, live on GCP.

FastAPIFAISS GeminiDocker GCP
Demo Video ↗ GitHub ↗

Problem

Manual resume screening doesn't scale, and most automated scorers give recruiters a number with no explanation.

Approach

Built a REST microservice combining keyword matching with FAISS + Sentence-Transformer semantic similarity for hybrid ranking, with Gemini-generated recruiter-style summaries streamed live via WebSockets. Containerized and deployed on GCP with batch processing and structured error handling so one bad resume can't take down a run.

Result

Iterative retrieval and ranking tuning raised top-candidate ATS match accuracy from ~70% to ~90%.

03 / Multi-Agent

Multi-Agent Blog Writing System

Orchestrator-worker pipeline with parallel fan-out agents.

LangGraphGPT-4.1 mini TavilyGemini Image API
GitHub ↗

Problem

Producing well-researched, structured long-form technical content end-to-end is slow for a single writer or agent.

Approach

An orchestrator agent plans sections (title, audience, tone, tasks); fan-out worker agents write in parallel; a reducer merges the output. An adaptive router picks closed-book, hybrid, or open-book generation depending on whether a topic needs research via Tavily, and an image-planning agent auto-generates technical diagrams through the Gemini Image API.

Result

Rewriting agent prompts for fact-grounding and strict instruction-following improved content quality by ~15% under rubric-based manual evaluation.

04 / Research-based

Self-Reflective RAG

Grounding verification and usefulness checks, built into the graph.

LangGraphFAISS OpenAI
GitHub ↗

Problem

Standard RAG has no built-in way to check whether a generated answer is actually grounded in what was retrieved, or even useful.

Approach

A LangGraph state machine adds an adaptive retrieval decision, strict relevance filtering, a grounding-verification step (IsSUP: fully / partially / not supported) with automatic revision, and a usefulness check (IsUSE) that triggers query rewriting and retry when an answer misses the question.

Result

A verification-first pipeline with retry-safe routing and quote-only revision — built to reduce hallucination at the source, not patch it after the fact.

06 / Product Thinking

AI Reddit Brand Monitor

Local-LLM sentiment dashboard for brand tracking.

OllamaPRAW StreamlitPlotly
GitHub ↗

Problem

Businesses need to know what's being said about them on Reddit without someone manually reading every thread.

Approach

PRAW-based scraping with a JSON fallback feeds a local LLM (via Ollama) that classifies each mention by sentiment, topic, and urgency. A Streamlit + Plotly dashboard visualizes the breakdown and auto-generates positive-feedback, negative-issue, and feature-request summaries.

Result

An end-to-end product loop — collection to actionable insight — running entirely on local inference, no API cost per classification.

07 / Evaluation Case Study

Hybrid Movie Recommender

Where the honest result mattered more than a clean win.

XGBoostMLflow DockerGCP
Demo Video ↗ GitHub ↗

Approach

Collaborative filtering (matrix factorization) and content-based filtering (TF-IDF) generate candidates, re-ranked by an XGBoost Learning-to-Rank model. Every experiment — hyperparameters, Precision@K, Recall@K, NDCG, Hit Rate — is logged in MLflow; deployed via Docker on GCP.

Honest Result

Evaluation showed the popularity baseline actually outperformed the trained ranker. Rather than hide that, I'm including it as a case study: rigorous, logged evaluation — and the willingness to report a model that didn't beat baseline — over a premature "it works" claim.
